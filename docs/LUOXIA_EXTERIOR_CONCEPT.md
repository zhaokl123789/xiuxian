# 落霞宗外部建筑：设计依据与首版实现

日期：2026-10-03。状态：按参考图实现外部首版；构建、几何检查和加强版完整 Forge 施工测试均已通过，游戏内视觉与普通服务器性能验收待完成。

## 任务边界与设定证据

本轮先制作现世的落霞山及宗门外部建筑群，内部维度仅预留入口。用户指定：顶级门派、位于落霞山、道胎强者坐镇、外部宏大壮观、先经过生图再建造。

这些是本项目采用的设计前提。本轮网上检索不足以确认小说的具体建筑平面、材料、殿名与峰数。以下布局和名称均为游戏设计，不能标注为小说原文事实；正式还原前需要可靠章节证据。不要用其他作品或同名宗门的内容补充原设定。

## 建筑方向

外部应有可辨识的山体轮廓，而非平地上的一座大房子。主峰高耸，侧峰与主峰有高低差；建筑沿真实支撑的山台分布，以登山道、栈桥和阶梯串联。山脚能够仰望主殿，山门到主峰形成有节奏的探索路线。

早期的 512×512 方块只是概念尺度。首版结合设计图和主世界高度采用 **321×385 方块**的实际范围，景观由山门、登山石道、山腰院落、主峰广场和大殿组成，辅以廊道、楼塔、观霞平台、瀑布和松林。建筑应有可进入的厅堂、台阶、走廊与连通路径。

视觉语言：深色石基、暖白墙体、赭红木柱、黛色层叠屋面与少量金铜装饰；落霞主要表现为赤金暮光、云海和屋脊轮廓，不能把全部方块涂红。可选加少量紫灰石材和琉璃装饰，必须由最终设计图确定。

道胎坐镇通过峰顶位置、空间尺度、护山设施和禁地入口的秩序表现；首版不把境界系统、NPC 或强者战斗实现混入建筑验收。

## 首版坐标与分层

所有坐标相对于管理员规划的原点。原点 Y 是山体的基准高度，原点 X/Z 定义平面中心；整座宗门固定朝南开门，沿负 Z 方向向北登山。

| 项目 | 首版范围或高度 |
| --- | --- |
| 局部 X 范围 | `-160..160`，共 321 方块 |
| 局部 Z 范围 | `-272..112`，共 385 方块 |
| 南侧入口方向 | 原点 `Z+108` 附近 |
| 第一层台地地面 | 原点 `Y+18` |
| 第二层台地地面 | 原点 `Y+48` |
| 第三层台地地面 | 原点 `Y+84` |
| 主峰台地地面 | 原点 `Y+132` |
| 后方岩峰最高点 | 原点 `Y+219` |
| 施工预留局部 Y 范围 | `-12..222` |
| 主世界原点 Y 范围 | `-52..97`，预留范围不超过可放置方块的 `Y=-64..319` |

主殿置于第四层台地，后方保留高耸岩峰。中轴为连续的宽石阶与院落，周边补充有栏杆的回廊、跨谷桥、侧殿与楼塔；崖壁、森林和瀑布形成侧向景观。内部维度只保留入口亭的位置，不放置可用的维度传送机制。

这些尺寸属于首版实现约束。调整比例、方向或高度时，必须同步修改布局、预览范围、定位与观察点，并再次检查楼梯和建筑之间的连接。

## 生图提示词 A：建筑群总体概念

生成一张可供 Minecraft 宗门建筑建造参考的高质量中国修仙建筑群概念图，横向 16:9，细节清晰。对象是本项目的落霞宗外部山门，位于落霞山，顶级宗门，道胎强者坐镇。不要宣称绘制了小说原文精确建筑。

一座高耸且轮廓鲜明的主峰，数座较低的侧峰，整座山拥有真实落地的石台和崖壁。宏伟中国古典宗门建筑沿山势层层升高：山脚大型山门、曲折登山石阶、山腰成组庭院和回廊、峰顶巨大主殿及开阔石坪。每一区域有清晰通路，屋顶群疏密有序，主殿是第一视觉焦点。山体、建筑群、云海与瀑布在画面中都清晰可辨。

画面为三分之二鸟瞰远景，看见完整山体和外部建筑群，夕阳从画面侧后方照入，赤金与紫灰晚霞，暖白墙体、深色石基、赭红木柱、黛色瓦顶、少量金铜屋脊。气质庄严、有传承、有秩序，壮观但不过度堆砌。阴影区保持细节可读。形体与屋顶适合后续翻译成方块，不要靠不可建造的细碎装饰制造效果。

约束：不出现现代建筑、西方城堡、科幻装置、巨大人物、文字、水印、满屏粒子、无支撑悬浮宫殿；不要用云遮住主体；不要把全部建筑做成红色；不要只画一座独立宫殿。外部图不展示内部维度。

## 生图提示词 B：俯视规划参考

以总体概念图为参考，生成同一宗门外部的高视角规划参考图，横向 16:9，正交或弱透视，白天中性光，所有建筑和路网清晰可读。保留相同的主峰位置、侧峰关系、材料与主殿轮廓。

突出山脚山门至主峰大殿的连续路径，区分山腰院落、回廊、山门广场、主峰广场、钟楼、观霞平台、瀑布与树林。建筑足迹、台地高差、楼梯、桥梁必须容易辨认；主殿下方留真实承台，每处院落有出入口。不要添加大量建筑把道路堵住，不画云层或浓雾，不加文字和尺寸标注，不改变总体图的建筑身份。这是建造布局参考，不是权威测量蓝图。

## 生图提示词 C：玩家视角与山门细节

以总体概念图为参考，生成同一落霞宗山门的玩家视角建筑参考图，横向 16:9。观察点在山脚登山路上，前景为石阶和雄伟山门，中景为依山石台、回廊和山腰院落，远处能仰望主峰大殿。强调人物能够行走的空间尺度、柱梁支撑、台阶和可进入的门洞。

材质与总体图一致：深色石基、暖白墙体、赭红木柱、黛瓦和少量金铜装饰。夕照落在屋檐、石阶和岩壁上，有中国修仙宗门的庄严感。细节能翻译成 Minecraft 的方块、台阶、楼梯、栅栏与墙，不依赖复杂曲面。不要满屏法术，不画人物特写，不加文字水印。

## 从参考图到可探索结构

1. 先审查总体图与俯视图是否一致，选择方向后确定尺度、材料表和山体高差。
2. 分别制作山门、院落、回廊、桥、钟楼、主殿等模板，保证有室内、有通路、有照明。
3. 组合山体和台地，再分区放置建筑；不能在玩家 tick 中一次性堆放整座宗门。
4. 在测试存档中提供管理员放置和定位方式，验证碰撞、台阶、路径、屋顶、光照及区块边界。
5. 对照概念图检查游戏截图；夜景、远景与近景均通过后，再纳入正式世界生成。

## 测试存档中的建造

施工只支持主世界。选择远离玩家建筑的地点，先备份测试存档；规划步骤只记录位置和显示范围，开始施工才替换范围内地形与方块。

验收时可使用创造物品栏“工具与实用物品”中的**落霞宗营建令**，或用 `/give @s xiuxian:luoxia_construction_decree` 获取。管理员创造模式右键地面顶面，默认以强制清场模式在北侧开始建造。施工范围内的地形、建筑、箱子与机器会直接移除；原版箱子、熔炉等容器先清空库存再移除，不掉落物品或熔炉经验。范围外的设施不会被清场。普通右键查进度与清场模式；施工中潜行右键暂停；暂停后潜行右键开启强制清场并继续，旧版因箱子、机器阻挡而暂停的施工同样适用。完工后潜行右键前往山门。清场与施工按区块分批执行，仍受主世界建造高度和管理员权限约束。

| 命令 | 用途 |
| --- | --- |
| `/xiuxian luoxia plan` | 以执行者脚下一个方块的位置规划 |
| `/xiuxian luoxia plan <x> <y> <z>` | 指定原点；示例 `/xiuxian luoxia plan 0 64 0` |
| `/xiuxian luoxia build` | 以保护模式开始施工，遇箱子、机器暂停 |
| `/xiuxian luoxia build force` | 以强制清场模式开始施工，移除箱子、机器并清空原版容器库存 |
| `/xiuxian luoxia status` | 查看位置、清场模式、施工状态与进度 |
| `/xiuxian luoxia locate` | 查询已规划宗门的位置 |
| `/xiuxian luoxia pause` | 暂停方块施工 |
| `/xiuxian luoxia resume` | 从保存的进度继续，保留记录中的清场模式 |
| `/xiuxian luoxia resume force` | 切换到强制清场，从保存的进度继续 |
| `/xiuxian luoxia visit entrance` | 完工后前往入口观察点 |
| `/xiuxian luoxia visit court` | 完工后前往院落观察点 |
| `/xiuxian luoxia visit summit` | 完工后前往主峰观察点 |

规划、建造、施工控制和观察点传送需要权限等级 2；观察点传送同时仅供创造或旁观模式使用。先查询范围再建造，不应在正式基地附近试放。暂停不会撤销已放置方块，首版也不提供自动回滚；需要恢复原地形时使用建造前的存档备份。

施工按区块分批处理并限制单次工作量，位置、版本、状态、清场模式和进度写入世界存档。重启不会重新从零建造；暂停状态应继续保留，活动施工可从保存进度继续。不要将数百万方块预先展开成驻留内存的完整清单，也不要在同一个玩家 tick 中同步施工全部区域。

## 外部刷新方式提案

建议最终每个世界有一处稀有、可定位的落霞山宗门，体现顶级门派的唯一性。本轮通过管理员规划后手动建造，每个存档只管理一处地点，不向正式存档自动生成。这里的单一施工地点是首版管理约束，自然生成的选址和稀有度仍待实现。

正式实现需比较：基于世界种子选择候选区域并记录唯一位置，或使用可配置的稀有结构分布。若允许多处同名宗门，就不能称为世界唯一。大型山体与建筑应按区块确定性生成，记录版本和生成范围，重载不得重复放置。

后续自然生成在旧存档中只考虑未生成区块，不能为了适配结构覆盖玩家已建造区域。普通探索可增加宗门地图或指引；管理员已有定位手段。内部门户先留建筑位置，维度和传送逻辑后续单独实现。

## 验收

### 自动检查入口

在项目根目录运行：

```powershell
.\gradlew.bat luoxiaVerify
.\gradlew.bat runGameTestServer
```

`luoxiaVerify` 直接组装与施工相同的方块蓝图，检查范围、连续登山轴线、门洞、主殿内部、跨谷廊桥、屋顶体量、岸堤，以及 NBT 状态和施工游标保存。输出 `build/luoxia-preview/luoxia-isometric.png` 和 `luoxia-central-axis.png`；这是颜色与方块形状简化后的诊断渲染，不能代替 Minecraft 材质、光照和玩家视角截图。该检查现在通过 Forge GameTest 启动，以保证自制方块注册完成；它只检查蓝图与状态，不等同于完整服务器施工测试。

`runGameTestServer` 通过 Forge 真实服务器 tick 和生产交互执行完整施工，覆盖非法选址、保护模式与强制清场、暂停与继续、施工进度的 NBT 往返、重复建造拒绝、实际通路、屋顶和区块接缝；同时检查初始化为紫府的测试修士，其身份和血量未被规划施工改变。该测试不等同于玩家跨维度、退出重连、真实服务器重启或真实客户端的回归测试。

强制清场版本的构建、几何检查和完整服务器测试于 2026-10-03 通过，Gradle 返回 `BUILD SUCCESSFUL`。几何检查记录 8,247,868 个占用方块、49 种方块状态、12,860 项蓝图操作，耗时 1.71 秒。完整服务器测试使用 `run/luoxia-gametest/world-1791024043388`，原点为 `4096 64 4096`，记录 8,708,678 次方块写入、16,042 个测试 tick、61.79 秒。普通命令保护箱子、营建令默认强制清场与旧任务升级、显式 `force` 命令、箱子/熔炉/刷怪笼及施工中新箱子的清除、容器库存清空且无物品掉落、范围外箱子与库存保留检查均通过；清场模式和施工游标的 NBT 恢复、旧存档默认保护模式、非法游标及越界写入保护检查也通过。

完整施工后，测试明确启用流体 tick，继续运行 200 tick，四处瀑布及两处湖岸的水源、落水柱、蓄水池、岸堤和干燥通道检查通过。上述耗时来自 GameTest 高速运行，不是普通 20 TPS 服务器的生成耗时或帧率测量。客户端画面未取得，真实服务器停服重启、玩家跨维度和常规服务器性能尚未验证。

测试空模板来自 `src/test/resources/gameteststructures/empty.snbt`，Gradle 准备任务会复制到 `run/luoxia-gametest/gameteststructures/`，并将 `src/test/resources/luoxia-server.properties` 复制为工作目录的 `server.properties`。该配置采用禁用自然结构的超平坦世界，避免自然生成的箱子等方块实体干扰测试主动放置的保护用箱子。服务器工作目录为 `run/luoxia-gametest/`，每次配置启动都生成 `world-<时间戳>` 的新世界目录，避免复用已存在落霞宗施工记录的世界。旧目录不会自动删除；服务器退出后可按需清理。测试只使用独立测试世界。

### 游戏内检查

- 从山脚可辨识主峰、主殿与山门；整体轮廓对得上选定概念图。
- 山门、山腰院落与主峰之间可步行到达，没有只可飞行通过的断路。
- 主殿等核心建筑可进入，有完整内部空间。
- 各区块重复加载不重造，不留下悬空半座建筑或跨区块裂口。
- 放置和加载时测量耗时，不卡死服务器。
- 此轮不修改玩家修行身份、属性或境界持久化逻辑。
