## 存档迁移

新洞天在世界加载阶段直接生成完整宗门、道胎宫和金丹宫及其通路，进入后不再逐段施工。`InitialBuildingsVersion` 保存初次生成完成状态，避免重进时覆盖玩家改动。旧版已采用第二版坐标、却还未完工的初次生成队列也在加载阶段补齐；确实从旧址搬迁的存档仍沿用以下分批迁移流程。首次创建洞天需要额外加载时间。

洞天基础版本仍为 3，保留地形种子、城镇、灵脉、Boss 区和自定义地标。接引阵用独立的 `ArrivalVersion` 记录迁移，完成后重新进入不重建接引阵。

已完成和施工中断的旧宗门、道胎宫、金丹宫均会在新位置重新排队。旧址分别按各自占地，从原地基底部到世界顶部完整清空，容器先清除库存。清场区域是独立盒体，不采用跨越城镇的总包围盒。

- 旧宗门山体：X `256..704`，Z `-776..-264`，Y `44..世界顶部`；移除后恢复该处石质地基和草地。
- 旧道胎宫：X `-220..220`，Z `-710..-290`，Y `78..世界顶部`。
- 旧金丹宫：X `-538..-182`，Z `56..384`，Y `110..世界顶部`。
- 更早的中央宗门、悬空占位宫和各条旧连接道路一并清理。

三处施工先完成清场和复扫，再开始建造，避免并行清理擦掉新道路。三个新址全部完工后，恢复共享交通节点和通往灵脉第一层的下降阶梯，使用 `RoutesVersion` 防止重复修改。

旧建筑占地及其旧道路上的玩家改动会随迁移清理；城镇接引阵预留区域也会一次性改建。上述区域之外的玩家物品和建筑保留。迁移后的建筑和接引阵保留后续玩家修改。

```mcfunction

/xiuxian sect inner visit entrance
/xiuxian daotai inner status
/xiuxian daotai inner visit entrance
```

`LuoxiaLayoutGameTests` 在真实洞天中同时迁移三处建筑，检查接引实际传送坐标、返回锚点、建筑间距、独立清场边界、旧容器移除、六次清场与建造游标恢复、共享节点和灵脉阶梯、完整宗门通路、音乐和坐席，以及重新进入后的唯一性。

布局、完整清场、宗门蓝图和资源、开局保护回归可一起运行：

```powershell
.\gradlew.bat runGameTestServer build --console=plain '-PgameTestNamespaces=xiuxian_layout,xiuxian_clearance,xiuxian_sect_geometry,xiuxian_sect_assets,xiuxian_startup'
```
